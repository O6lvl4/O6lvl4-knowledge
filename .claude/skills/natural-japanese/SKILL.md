# Natural Japanese

対象ファイル: `$ARGUMENTS`

vault のノートなら `vault/` プレフィクスを含めること (例: `vault/cots.md`)。

## 現在の内容

!`cat "$ARGUMENTS" 2>/dev/null || echo "(file not found)"`

## 計測

!`f="$ARGUMENTS"; if [ -f "$f" ]; then L=$(wc -l < "$f" | tr -d ' '); echo "行数: $L"; B=$(( $(grep -o '\*\*' "$f" | wc -l | tr -d ' ') / 2 )); T=$(( $(grep "^|" "$f" | grep -o '\*\*' | wc -l | tr -d ' ') / 2 )); echo "太字: 総$B (表内$T / 散文$((B-T)))"; echo "--- 手癖 ---"; for p in "ではなく" "ではない" "が肝" "が要点" "本質" "決定的" "圧倒的" "にほかならない" "そのもの" "つまり" "要するに" "にあたる" "ということになる" "に他ならない"; do n=$(grep -o "$p" "$f" | wc -l | tr -d ' '); [ "$n" -gt 0 ] && printf "%-16s %s\n" "$p" "$n"; done; echo "--- 太字2つ以上の散文行 ---"; grep -nv "^|" "$f" | grep -cE "\*\*.*\*\*.*\*\*.*\*\*"; else echo "(file not found)"; fi`

## この推敲が狙うもの

読み手が「納得感が薄い」と感じるとき、原因は内容の不足とは限らない。**主張の強さだけが上がって、根拠が運ばれていない文章**が続くと、読者は押し切られた感覚だけを受け取る。以下はその状態を作る具体的な型で、いずれも計測できる。

## 検出する型と直し方

### 1. 否定で定義する (最優先)

**型**: 「X ではなく Y」「X ではない。Y だ」

**なぜ悪いか**: 否定は主張を強く見せるが、**証拠を1つも運ばない**。読者は「A ではない」と繰り返し言われるだけで、なぜ B なのかを示されない。同じ型が続くと、内容ではなくリズムで押している文章になる。

**直し方**: 肯定形で定義し、否定が要るなら後置する。

- 悪い: 「これは比喩ではなく、最小構成である」
- 良い: 「これは最小構成にあたる。比喩として導入されたものではない」

主張を先に立てると、否定は補足の位置に落ちる。

**残してよい場合**: 対比そのものが主張の中身であるとき。「忘れたは、消えたのではなく、たどり着けなくなった状態を指す」はこれにあたる。

**目安**: 100行あたり3回まで。

### 2. 強調の飽和

**型**: 太字の乱発。

**なぜ悪いか**: 全部を強調すると、何も強調されない。さらに、太字は「ここが重要だ」と宣言する行為なので、多用は**示す代わりに言い張る**姿勢に見える。

**直し方**: 定義語の初出と、節の結論だけに絞る。1段落に2つ以上あったら、後ろを外す。

**目安**: 散文で4〜5行に1つ。表の中は別枠で数える。

### 3. 断定で締め続ける

**型**: すべての段落がキメ台詞で終わる。

**なぜ悪いか**: 全段落が結論の重みを持つと、どれが本当の結論か分からなくなる。演説の調子になり、検討している文章に見えなくなる。

**直し方**: 導出・条件・限界で終わる段落を混ぜる。「ただし〜の場合は別」「これは〜を仮定している」で終わる段落があると、断定した段落が際立つ。

### 4. 手癖語

「〜が肝」「〜が要点」「本質は」「決定的」「圧倒的」「〜にほかならない」「つまり」「要するに」。

**直し方**: 削って意味が変わらないなら削る。「つまり」「要するに」の後ろに本質があるなら、**その前が冗長**という証拠なので、前を削って後ろだけ残す。

### 5. 圧縮しすぎ

**型**: 短くまとまっているが、単体では意味が取れない一文。

例: 「同じ総時間を間隔を空けて配る」 — 書いた側は分かるが、読者にはなぜ「同じ総時間」と断るのかが分からない。

**なぜ悪いか**: 要約に見えるが、実際には暗号になっている。密度は上がっていない。

**テスト**: その1行だけを、前提を知らない人に見せて意味が通るか。通らなければ、1文足す。

### 6. 定義せずに使う語

**型**: 用語が初出で定義されないまま使われる。**節タイトルに使われている語は特に危ない**。

**検出**: 主要な用語の初出行を探し、その手前に定義があるか確認する。前節と用語がつながっているかも見る（前節が「量」の話で終わり、次節が「軸」で始まっていたら、橋が要る）。

### 7. 確度の混同

**型**: 実証された事実と、枠組みからの解釈が、同じ強さで書かれている。

**直し方**: 「これは本ノートの解釈であって、出典の主張ではない」と書き分ける。確度の差を示すと、確度の高い主張の信頼が上がる。

## 手順

1. 上の計測結果を読み、閾値を超えている型を特定する
2. 該当箇所を1つずつ直す。**機械置換をしない** — 型ごとに文の組み替えが必要で、単語の置き換えでは直らない
3. 構成レベル(型5〜7)を点検する。ここは計測に出ないので、通読して探す
4. **再計測する**。書き足したり組み替えたりすると癖は再発する。実績として、導出を書き足した際に「ではなく」が 8回 → 27回 に戻った例がある。再計測を省かない
5. `updated_at` を現在時刻に更新する (時刻まで含めた ISO 8601)
6. 表を編集した場合は列数の一致を確認する

## アンチパターン

- **意味を変える**: 文体を直す作業であって、主張を変える作業ではない
- **一律置換**: 「ではなく」を全部消すと、対比が主張である箇所まで壊れる
- **削りすぎ**: 強調をゼロにすると、今度は起伏がなくなる。目的は適正化であって撲滅ではない
- **計測だけして満足する**: 数字が下がっても、読んで良くなっていなければ意味がない
- **再計測の省略**: 直す過程で新しく書いた文に、同じ癖が入る
